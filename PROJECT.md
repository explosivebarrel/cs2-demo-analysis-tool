# CS2 Demo Analyzer — описание проекта

Веб-утилита для детального анализа демо-файлов Counter-Strike 2 (уровень Leetify/scope.gg):
общая сводка матча, подробная статистика и скоринг каждого игрока, хитмапы на радаре
карты (2D и 3D), покадровый реплей матча «что происходило в любой момент времени»
(2D и 3D), aim/duel-метрики с покадровым разбором эпизодов.

Бэкенд и фронтенд полностью запускаются в Docker (`docker compose up`), единственный
вход — порт **8080**.

Инструкции для ИИ-агентов: [AGENTS.md](AGENTS.md). Методология метрик: [METRICS.md](METRICS.md),
семантическая спецификация: [METRICS_SPEC.md](METRICS_SPEC.md). Заметки прошлых сессий: [memory/](memory/).

## 1. Архитектура

```
┌────────────────────────────────────────────────────────────┐
│  docker compose                                            │
│                                                            │
│  frontend (nginx:alpine)          backend (python:3.12)    │
│  ├─ Vite+React+TS SPA (static)    ├─ FastAPI + uvicorn    │
│  └─ reverse-proxy /api → backend  ├─ demoparser2 (Rust)   │
│                                   ├─ pandas / numpy       │
│     :8080 ─────────────────────►  └─ worker-subprocess    │
│                                        (анализ демо)       │
│                                                            │
│  volumes:                                                  │
│   ./demo-examples  → /data/inbox  (ro, примеры демок)      │
│   cs2_store        → /data/store  (uploads, артефакты,     │
│                                    кэш радаров)            │
└────────────────────────────────────────────────────────────┘
```

- **Backend** — FastAPI. Загрузка демо, реестр (inbox + uploads), фоновый анализ
  (subprocess `python -m app.worker`, прогресс по фазам в `status.json`), отдача
  артефактов анализа, радары карт и overview-геоданные. Без БД — всё на диске.
- **Frontend** — SPA на React + TypeScript (Vite), сборка в Docker (multi-stage),
  раздача nginx'ом, проксирование `/api`. Локальный Node не нужен.
- **demo_id** — хэш `sha1(имя:размер)`; артефакты анализа в `/data/store/analyses/<id>/`.

## 2. Пайплайн анализа (backend/app/pipeline/)

| Фаза | Модуль | Что делает |
|---|---|---|
| загрузка | `context.py` | header, `parse_events` (~30 ивентов), тики чанками с даунсемплом (шаг `CS2_FRAME_SECONDS`, по умолчанию ~0.125 с), гранаты, определение tickrate |
| раунды | `rounds.py` | сегментация раундов, стороны T/CT, победители (FACEIT-демо без `round_end` → вывод из bomb-ивентов + живых игроков), закупки, opening kills, MVP, пистолетки, тайминги |
| кадры | `replayframes.py` | покадровый стрим (payload v2: 13 значений на игрока: xyz/yaw/hp/armor/alive/weapon/flags/team/equip/money/ammo + спарсный журнал инвентаря `inv`), статистика живости/дистанции/«long holds» (стоянки >5 c, с z-координатой), трекер клатчей 1vX, состояние бомбы |
| игроки | `players.py` | K/D/A, урон (dealt/taken/util/post-plant/по хитгруппам), трейды (списки событий, не флаги), тимкиллы (счётчик + эпизоды), мультикиллы, флешки (враги ослеплены, blindSec, эффективные), гранаты, бомба, экономика, KAST (traded rounds считаются) |
| рейтинг | `rating.py` | Rating 2.1 (approx, веса `RATING_WEIGHTS`): саб-рейтинги kill/survival/damage/KAST/impact, нормировка на 1.00 по матчу |
| события | `events.py` | компактная лента для плеера: киллы, трейлы гранат, детонации/зоны смоков и огня, бомба, выстрелы (трассеры), вспышки с длительностью, границы раундов |
| хитмапы | `heatmaps.py` | слои: kills, deaths, damage (dealt/taken), shots, flash_throws/hits, smokes, molotovs, hes, plants, defuses, opening_duels, clutches, holds, positions — **все точки с z-координатой** (кроме легаси-артефактов) |
| хитмапы 3D | `heatmap3d.py` | воксельная сетка позиций: аккумулятор (ix, iy, iz, игрок) по живым/на земле/в раунде сэмплам; пишет `heatmap3d.json.gz` (только при наличии вокселей); `shades` вставляется на лету из `CS2_HM3D_SHADES` |
| win-вероятность | `winprob.py` | кривая вероятности победы по кадрам (график в реплей-плеере): пост-плант — бомбовое время с китами/фьюзом/активным дефьюзом; дефьюз аннулирует fallback-фьюз; окно заплантованого ограничено концом раунда |
| дуэли/impact | `playeranalytics.py` | классификация дуэлей с тегами ошибок (moving_shot, isolated, flashed, missed_first, overshoot/undershoot, strong_duel…), per-duel winProb, per-player impact, mapEvents, teamkill-эпизоды; покадровые записи эпизодов (скорость из позиционных дельт через VelIndex — центральная разность на произвольном тике, WASD-вывод из вектора движения vs yaw, выстрелы, окна для «моментов»: clutch/multikill/openingDeath/mistake/teamkill/swing) |
| aim-механики | `aim_mechanics.py` | reaction time (все/успешные), time-to-kill, выстрелы в движении, first-bullet accuracy, честный crosshair placement (угол прицела на пике жертвы, ≤25°), excellent contacts, overshoot/undershoot (единый источник), reload-ошибки, контроль углов |
| чат | `chat.py` | текстовый чат матча |
| прогресс | `progress.py` | распределение прогресс-бара по измеренным длительностям стадий (store/stage_times.json, скользящие 10); `CS2_PROGRESS_WEIGHTS` пиннит веса вручную |
| оркестратор | `run.py` | собирает всё, пишет артефакты: `analysis.json.gz`, `replay.json.gz`, `heatmap.json.gz`, `heatmap3d.json.gz` (при данных), `player_analytics.json.gz`, `chat.json.gz` |

Отдельно есть **probe** (`probe.py` + `POST /api/demos/{id}/probe`): быстрый (2–5 с)
неполный парс для карточек списка демок (карта, команды, счёт) без полного анализа.

Прогресс фаз больше не фиксированный: каждая стадия получает диапазон 2–98%
пропорционально медианным длительностям из `stage_times.json` (бенчмарк-driven,
`progress.py`); две длинные стадии отдают подпрогресс (ticks 70–78, analytics 92–96).

## 3. Метрики

**Матч**: карта, сервер, tickrate, длительность, счёт по половинам, названия команд,
пистолетные раунды, «моментум», типы закупок по раундам, планты/дефьюзы, MVP раундов,
причины побед (elimination/bomb/defuse/time), экономика команд.

**Раунд**: длительность, победитель и причина, opening kill (кто/на кого/оружие),
банк и тип закупки (pistol/eco/force/full), бомба (сайт, плантер, дефьюзер, kit),
клатчи, счёт на момент раунда.

**Игрок** (всё — за матч и в разбивке T/CT):
- База: K/D/A, flash-assists, K/D diff, KPR/DPR/APR, HS%, KAST% (traded rounds
  засчитываются), ADR, utility ADR, урон полученный, урон по тиммейтам, post-plant урон.
- Дуэли: opening kills/deaths/winrate, trade kills / traded deaths (списки событий
  (round, tick), не флаги), дистанции киллов (avg/max, бакеты по метрам).
- Мультикиллы: 2K/3K/4K/5K(ACE), раунды с мультикиллом.
- Клатчи: сыграно/выиграно, разбивка 1v1…1v5, список с деталями.
- Тимкиллы: счётчик на игрока + эпизоды с контекстом (страница
  `/metrics/teamKills`), лёгкий блок «кто → кого» на обзоре матча, моменты в реплее.
- Утилити: флешки (брошено/врагов ослеплено/секунд ослепления/эффективные/тиммейтов),
  смоки, молотовы/зажигательные, HE, декои, утилити-урон.
- Бомба: планты, дефьюзы, попытки, с китом.
- Оружия: таблица по каждому (киллы, HS%, выстрелы, попадания, точность, урон).
- Хитгруппы (head/chest/stomach/arms/legs/generic).
- Экономика: средний spend, всего потрачено.
- Движение: дистанция (км), время живости за раунд, survival%, сейвы.
- Скоринг: Rating 2.1 (approx) + разложение на 5 саб-рейтингов, RWS, per-round IMP.
- По раундам: серия k/d/a/dmg/kast для графиков.
- История: результаты прошлых матчей игрока (FACEIT, `playerHistory.json`) с трендом
  Rating/KAST/RWS/IMP и фильтром по картам.

**Aim и дуэли** (страница метрик игрока, 21 подстраница; семантика — METRICS_SPEC.md):
- Реакция: «время до первого выстрела на пике» (реакция + подводка), успешные реакции.
- Стрельба: time-to-kill, first-bullet accuracy, overshoot/undershoot,
  честный crosshair placement (угол прицела на пике жертвы ≤25°),
  excellent contacts (остановился → попал → убил), потеря патронов при перезарядке.
- Движение: выстрелы в движении (бывш. контрстрейф-ошибки), идеальные стрейфы,
  пики на шифте (shift-peek %).
- Дуэли: список с тегами ошибок (missed_first, moving_shot, isolated, flashed,
  passive_angle, strong_duel, outnumbered…), win probability по дуэли, разбор эпизода
  (EpisodeDrillDown v2, 2D и 3D): приближенная миникарта эпизода (камера на барицентре
  участников, все игроки и гранаты), график скорости (0–250 u/s, VelIndex — центральная
  разность на произвольном тике), вертикальные линии выстрелов (белый cap = попадание),
  таймлайны нажатий W/A/S/D/Space/Shift/Ctrl (выводятся из вектора движения vs yaw —
  prop `button_states` в FACEIT-демках недоступен), лог событий с таймкодами;
  всё синхронизировано общим курсором.
- Качество контактов: excellent contacts, lost duels, passive angles, isolation %.
- Бенчмарки: каждая метрика сопоставляется тирам weak/avg/good/elite (`/api/benchmarks`);
  тиры часть метрик не перекалиброваны после ревизии популяций (кластер C — отложено).

## 4. Хитмапы (canvas поверх радара, 2D + 3D)

Слои: `kills`, `deaths`, `damage`, `damage_taken`, `shots`, `flash_throws`,
`flash_hits`, `smokes`, `molotovs`, `hes`, `plants`, `defuses`, `opening_duels`,
`clutches`, `holds` (стоянки: размер = длительность), `positions` (плотность позиций).
Все точки несут z-координату (дописана в конец кортежа; старые артефакты без z
читаются с fallback на уровень земли).

Фильтры: игроки (мультивыбор, маппинг через fb-порядок `heatmap.players`),
команда, сторона T/CT, половина матча, фаза раунда (freeze/early/mid/late),
пистолетные, z-уровень (upper/lower для nuke/vertigo).
Рендер 2D: радиальные градиенты (additive), пресеты цветов, радиус/интенсивность.

**3D-режим** (переключатель 2D|3D, контролы общие): орбитальная камера
(драг — поворот, Shift/ПКМ — панорама строго по земле, колесо — зум, 2x клик — сброс,
дефолт — изометрия). Сцена: воксельная поверхность карты (нижние грани вокселей
плотности позиций из `heatmap3d.json.gz`, детализация 32/64/128), радар-подложка
(аффинная проекция на плоскость земли), облако точек слоя на реальных высотах.
Контролы 3D: прозрачность точек (общая с 2D), прозрачность карты, подложка вкл/выкл,
контрастные тайлы (hue+180 к цвету слоя), оттенки тайлов (слайдер 1–32,
серверный дефолт `CS2_HM3D_SHADES` — применяется на лету без реанализа).

## 5. Реплей-плеер (2D + 3D)

Кадры каждые ~0.125 с (шаг настраивается `CS2_FRAME_SECONDS`): позиции всех игроков
(xyz, yaw, hp, armor, alive, активное оружие + инвентарь из спарсного журнала, флаги:
несёт бомбу/kit/ослеплён/скоуп/идёт тихо/присел), состояние бомбы (носится/брошена/
заложена/взорвана/обезврежена), трейлы гранат, зоны смоков и огня, вспышки с честной
длительностью ослепления (жёлтый пирог на точке игрока), трассеры, лента киллов,
границы и исходы раундов. Фронт интерполирует позиции/yaw между кадрами (lerp с
защитой от телепортов и смертей/спавнов), поэтому проигрывание плавное при любом zoom.
Канвас letterbox: карта всегда вписана в блок любого размера (zoom=1 = «гарантированно
вмещается»). Управление: play/pause, скорость 0.5–8x, скраб-таймлайн с раундами и
маркерами событий.

**3D-режим** (кнопка 3D / хоткей `3`, выбор запоминается): та же орбитальная камера,
что у хитмапов. Сцена: воксельная поверхность карты из `heatmap3d` + радар-подложка +
игроки-капсулы (полусферы+цилиндр, цвет команды) с сектором взгляда (полоска-дуга
1.1–1.3R на высоте середины, скруглённые концы), номером и иконкой оружия над капсулой,
HP-баром под ней, скоростью с направлением движения справа (как на 2D); бомбоносец —
белое кольцо на земле. Гранаты-трейлы с высотой, трассеры от уровня глаз, зоны смоков/
огня диски на земле, заложенная бомба — пульсирующий диск. Игроки на другом уровне
карты затемнены. Эпизоды дуэлей на странице игрока тоже имеют 3D-режим (та же камера).

| GET | `/api/demos/{id}/chat` | чат матча |
| POST | `/api/demos/{id}/probe` | быстрый неполный парс (карта/команды/счёт, 2–5 с) |
| GET | `/api/demos/{id}/player/{steamid}/analytics` | дуэли, aim-метрики, impact, эпизоды игрока |
| GET | `/api/players/{steamid}/history` | история матчей игрока (FACEIT, для вкладки History) |
| GET | `/api/benchmarks` | тиры метрик (weak/avg/good/elite) |
| GET | `/api/settings` | runtime-настройки (store/settings.json; API key write-only, маскируется) |

| GET | `/api/autoimport` | статус автоимпорта (watch-папки + FACEIT) |
| WS | `/ws/demos` | статусы анализа в реальном времени |

Радары берутся из открытого репозитория
[MurkyYT/cs2-map-icons](https://github.com/MurkyYT/cs2-map-icons)
(`images/radars/<map>_radar_psd.png` + `data/radar_info/<map>.txt`),
кэшируются в volume; при отсутствии сети — тёмная сетка-заглушка.

## 6.1. Автоимпорт демок (опционально)

Оба механизма включаются env-переменными (см. docker-compose.yml), по умолчанию выключены:

| Переменная | Что делает |
|---|---|
| `CS2_WATCH_DIRS` | pathsep-список папок, которые сканируются на новые `.dem/.dem.zst/.dem.gz/.zst/.gz` (внутренние пути контейнера; папки монтируются volumes). Новый файл → импорт в uploads → авто-анализ. Уже существующие файлы при старте НЕ импортируются (только запоминаются). |
| `CS2_WATCH_POLL_SEC` | период сканирования (по умолчанию 20). |
| `CS2_FACEIT_API_KEY` | персональный API-ключ FACEIT (faceit.com → настройки → PERSONAL API KEY). |
| `CS2_FACEIT_PLAYER_ID` | ID игрока из URL профиля `faceit.com/players/{id}`. |
| `CS2_FACEIT_POLL_SEC` | период опроса истории матчей (по умолчанию 300). |
| `CS2_IMPORT_WINDOW_HOURS` | окно автоимпорта в часах (по умолчанию 12, пресеты 1–72): файлы старше окна не качаются автоматически, а попадают в `store/suggestions.json` и показываются на странице демо с кнопкой «Скачать и анализировать». |

Runtime-настройки: `store/settings.json` перекрывает env-дефолты; страница `/settings`
(watch-папки, поллинг, ключ/ID FACEIT; ключ write-only и маскируется), сохранение
перезагружает автоимпорт на лету.

FACEIT-поллер раз в период запрашивает историю матчей игрока
(`open.faceit.com/data/v4`, Bearer-авторизация; история пагинируется на глубину окна),
скачивает демки новых матчей и запускает анализ. Скачивание: у совпадения берётся
`cloud resource url` и обменивается на прямую ссылку через Downloads API
(`POST /download/v2/demos/download`); для этого у ключа должен быть scope `downloads`
(отдельное приложение) — без него кнопка скачивания показывает понятную ошибку 403.
Ошибки сети/ключа пишутся в лог бэкенда и не роняют API. Происхождение демки видно
в meta-файле `<id>.dem.name` (`origin`: upload / watch / faceit).

Иконки оружия/снаряжения в UI — SVG из игры, собранные репозиторием
[Juknum/counter-strike-icons](https://github.com/Juknum/counter-strike-icons);
ассеты Valve (некоммерческое использование в fan-проектах). Файлы бандлятся в
`frontend/public/icons/weapons/`, маппинг на канонические ключи — `WeaponIcon.tsx`.

## 7. UI (RU по умолчанию + переключатель EN)

Тёмная CS-стилистика (оранжевый акцент, T=оранжевый/CT=синий). Маршруты:
`/` — демо, `/match/:id` — обзор, `/match/:id/player/:steamid` — игрок (вкладки:
overview, impact, duels, weapons, map, rounds, history), `/match/:id/player/:steamid/metrics/:key`
— 21 подстраница aim/duel-метрик, `/match/:id/heatmaps`, `/match/:id/replay`,
`/settings` — runtime-настройки автоимпорта, `/about` — документация формул (Rating,
RWS, KAST, IMP). Реплей — отдельный полноэкранный экран (кнопка «Реплей» справа в
навигации матча), вкладка чата удалена (backend продолжает писать `chat.json.gz`).

1. **Демо** — список (inbox+uploads+suggestions), карточки с картой/счётом/датой (из
   probe), WS-статусы парсинга (fallback-поллинг), drag&drop загрузка пачкой файлов
   с видимым прогрессом каждого, предложения «скачать и анализировать» из окна
   автоимпорта (бейдж источника FACEIT/папка).
2. **Обзор матча** — счёт, сравнение команд, сортируемый скорборд, таблица раундов,
   блок тимкиллов «кто → кого».
3. **Игрок** — 7 вкладок + карточки метрик с бенчмарк-тирами, разбор дуэлей покадрово
   (2D/3D), история матчей с трендом Rating/KAST/RWS/IMP.
4. **Метрики** — детальная страница каждой aim/duel-метрики: summary, шкала,
   сравнение winrate, сетка раундов, эпизоды.
5. **Хитмапы** — радар + 16 слоёв + фильтры (игрок/сторона/фаза), прозрачность, зум;
   переключатель 2D|3D с общей панелью контролов.
6. **Реплей** — полноэкранный плеер: карта по центру со свободным зумом 0.1–10x,
   слева дравер События/Моменты, справа команды с раскрываемыми карточками игроков
   (HP, броня, деньги, оружие+патроны, инвентарь, скорость), снизу play/±5с/моменты,
   гранаты-dropdown с типами, скорости и winprob-таймлайн раунда; сверху переключатель
   раундов (WU/KR/раунды со скрабберами) и кнопка 3D; хоткеи (Space, ←/→, H/F, 0, [/],
   3 — 3D), скрытие интерфейса и полноэкранный режим, легенда хоткеев отдельной кнопкой.

### Известные допущения
- Rating 2.1 — приближение (HLTV не публикует формулу); в UI помечаем «approx».
- Экономика команд — сумма `cash_spent_this_round` на первом тике раунда.
- MVP раунда — максимум урона в победившей команде (в FACEIT-демо нет round_mvp).
- Победа по таймеру — эвристика «живых больше у CT на конце раунда».
- «Сейв» = проиграл раунд и выжил.
- aim-метрики (реакция, стрейфы, TTK) — собственные эвристики поверх тиков/ивентов,
  а не официальные значения игры.
- WASD в эпизодах дуэлей — вывод из вектора скорости и yaw (button_states недоступен
  в FACEIT-демках); Space/Shift/Ctrl — по событиям player_jump / is_walking / duck_amount.
- Скорость в эпизодах — VelIndex (центральная разность по индексу сэмплов), работает
  на любом тике; props `velocity_*` демопарсера на прореженных тиках завышены.
- Сектор взгляда в 3D-реплее — 60° дуга, форма ждёт референс от пользователя.

## 10. Как это запускать (после завершения работ)

```bash
docker compose up --build     # сборка и запуск
# UI:      http://localhost:8080
# API:     http://localhost:8080/api/health
```

Дальше: выбрать демо в списке → «Анализировать» → страницы Обзор/Игроки/Хитмапы/Реплей.
