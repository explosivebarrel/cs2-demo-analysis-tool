# METRICS.md — методология расчёта метрик (инженерная документация)

Документ описывает, **как реально считаются** метрики анализатора на бэкенде:
какие данные демки читаются, какие алгоритмы и пороги применяются, какие
упрощения приняты. Пользовательская версия (кратко, с формулами) — страница
`/about` в UI. Семантика (зачем метрика, триггеры, случаи) — первичный документ
[METRICS_SPEC.md](METRICS_SPEC.md). Этот файл — инженерная сводка.

Источники данных: события демки читаются через [demoparser2](https://github.com/LaihoE/demoparser)
один проход (`pipeline/context.py`). Тики сэмплируются с шагом 0.125 с
(`frame_step = max(4, round(tickrate * 0.125))`). Все временные окна заданы в
секундах и переводятся в тики через фактический tickrate (детектится по медиане
шага `game_time`, поддерживаются 64/128).

Константы и пороги: `backend/app/config.py`, `pipeline/aim_mechanics.py`.

## Раунды и команды (`pipeline/rounds.py`)

| Понятие | Алгоритм |
|---|---|
| Границы раунда | от `round_freeze_end` до `round_officially_ended` (или `round_prestart` следующего). Раунды без конца, киллов и бомба-событий (отменённые/рестарты) отбрасываются |
| Победитель | 1) авторитетно: `round_end.winner` (`"T"`/`"CT"`) с reason-маппингом (`bomb_defused`→defuse, `bomb_exploded`→bomb, `*_killed`→elimination, `time/saved`→time); 2) fallback: бомба-события + живые игроки на конце раунда (с докруткой смертей после последнего сэмпла). `hostage_rescued` → победа CT |
| Стороны | `team_num` на первом тике раунда (2=T, 3=CT); identity команд — два крупнейших клана с непересекающимися tnum-множествами, fallback — стороны первого раунда |
| Сайты | `bomb_planted.site` — id зоны; уникальные id матча сортируются и маппятся на A/B (эвристика, не гарантия официального нейминга) |
| MVP раунда | максимум урона по **врагам** среди игроков победившей команды |
| Пистолетные | первый раунд каждой половины (смена сторон) |
| Закупки | `cash_spent_this_round` на тике `buytime_ended` (или freeze_end): pistol ≤1000, eco <1900, force <3900, full ≥3900 — по **среднему на игрока** команды, только реальные игроки |

Упрощения: победа «по времени» эвристикой всегда отдаётся CT (на hostage-картах
учтён `hostage_rescued`); бай-тайм ~20 с после фриза — траты читаются на его конце.

## Базовые метрики игрока (`pipeline/players.py`)

- **K/D/A** — `player_death`; ассистенты — `assister_steamid` (не атакующий и не
  жертва); flash-assist — `assistedflash`.
- **ADR** — сумма `player_hurt.dmg_health` по врагам / раунды. Урон вне раундов
  (разминка) исключается. demoparser2 отдаёт фактически снятый HP (overkill не
  завышает). utilDmg — урон гранатами; postPlantDmg — после `bomb_planted`.
- **HS%** — `headshot` в `player_death`.
- **KAST%** — раунд засчитывается, если был kill, assist, flash-assist, выжил
  или смерть отомщена (trade). «Выжил» — жив на последнем кадре раунда **и**
  не умер между последним сэмплом и концом раунда (проверка по `player_death`).
  Раунд, где смерть игрока отомщена, идёт в KAST как traded round (список
  `tradedDeathEvents` — единственный источник и для KAST, и для tradedPct).
- **Трейды** — окно 5 с (`TRADE_WINDOW_SECONDS`): tradeDeath — убийца жертвы сам
  убит тиммейтом жертвы в течение окна; tradeKill — соответствующий килл мстителя.
  Хранятся как списки событий (round, tick), а не пер-раундные флаги — один килл-
  мститель = один tradeKill, каждая отомщённая смерть = tradedDeath.
- **Тимкиллы** — киллы по своим (счётчик `teamKills` на игроке + матч-список в
  `analysis.teamKills` + эпизоды с контекстом в player_analytics, страница
  `/metrics/teamKills`, момент в реплее); kills при этом не уменьшаются
  (осознанное отличие от скорборда CS2).
- **Мультикиллы** — киллы по врагам в одном раунде (тимкиллы не считаются):
  2K/3K/4K/5K.
- **Открывашки** — первый килл раунда по врагу (тимкиллы не открывают).
- **Клатчи** — `ClutchTracker` по кадрам: остался 1 против ≥2 → attempt с
  maxEnemies; won = клатчер в команде-победителе. 1v1 не считается (осознанно).
- **Сейвы** — выжил в проигранном раунде.
- **Флешки** — брошено (по `parse_grenades`), врагов ослеплено (`player_blind`,
  враг), секунд ослепления, эффективные (≥2.2 c, `FLASH_EFFECTIVE_SECONDS`),
  ослеплённые тиммейты — отдельно.
- **Движение** — дистанция (юниты × 0.01905 = метры), время живости, сейвы.
- **Оружия** — киллы/HS из `player_death`, попадания/урон из `player_hurt`,
  выстрелы из `weapon_fire` (только стрелковое) → точность.
- **Экономика игрока** — средний/суммарный `cash_spent_this_round`.

## Скоринг (`pipeline/rating.py`)

- **Rating 2.1 (approx)** — пять саб-рейтингов, нормированных на среднее 1.00 по
  матчу, веса: kill 0.30 (киллы + 0.5×openings + 0.25×«чистые» киллы), survival
  0.25 (смерти со штрафом +0.4 за opening-death и скидкой 0.4 за отомщённую),
  damage 0.20 (ADR), kast 0.15, impact 0.10 (раунды с мультикиллом ×2 + клатчи
  + openings). Формула HLTV закрыта — это документированное приближение.
- **RWS** — доля урона игрока в уроне команды в выигранных раундах (канон).
- **IMP** — per-round: opening kill в победе +2.0 / в поражении +0.5, opening
  death в победе −0.5 / в поражении −1.0, доп. килл +0.5, клатч +1.5, сейв +0.2.

## Aim-метрики (`pipeline/aim_mechanics.py`)

Учитывается только **стрелковое** оружие (гранаты/нож/Zeus/C4 отфильтрованы,
имена нормализуются `canon()`). «Дуэль» = цепочка выстрелов с паузой ≤2 с
(`DUEL_MERGE_SEC`). Попадание пули — `player_hurt` в пределах 0.15 с после
выстрела (`BULLET_HIT_WINDOW_SEC`).

| Метрика | Алгоритм |
|---|---|
| reactionTimeMs | «peek onset» = тик, где жертва разогналась (скорость > 30 u/s) в окне 2 с до первого выстрела; RT = выстрел − onset. Жертвы, простоявшие всё окно (pre-aim сценарий), исключаются. UI: «Время до первого выстрела на пике» |
| successfulReactionTimeMs | то же, только дуэли, где первая пуля попала |
| ttk_ms | первый выстрел → килл в выигранных дуэлях, окно поиска 3 с (`TTK_MAX_SEC`) |
| firstBulletAcc | % дуэлей, где первая пуля попала (hurt врагу в 0.15 с, только враги) |
| missed_first (тег дуэли) | первая пуля дуэли не дала урона в окне |
| counterStrafeErrors | выстрелы на скорости > 50 u/s (все движущиеся выстрелы — UI переименовано в «Выстрелы в движении», см. METRICS_SPEC §6) |
| idealStrafePct | % дуель-открытий с киллом, где игрок был остановлен |
| crosshairPlacementPct | **честная семантика (кластер B)**: в момент начала пика жертвы (скорость > 30 u/s) — угол между yaw атакующего и направлением на жертву; хорошая подводка ≤ 25° (`CROSSHAIR_PLACEMENT_DEG`); `crosshairGoodTicks` — эпизоды для страницы |
| overshootCount | won-дуэли со сменой знака угловой ошибки > 10° (единый источник для карточки, страницы и тега `overshoot`); `undershoot` — монотонный рост ошибки |
| excellentContacts | «идеальный контакт»: остановился (≤50 u/s) → первая пуля попала (0.15 с) → килл (2 с); эпизоды `excellentContactTicks` |
| reloadErrors | перезарядки с >5 патронами в магазине (по ammo ближайшего тика; без ammo — все перезарядки) |
| angleControlCount | позиции, удерживаемые ≥2 с со скоростью <30 u/s, дедуп сеткой 64 юнита |

## Дуэли (`pipeline/playeranalytics.py`)

Дуэль = килл игрока (или его смерть) + контекст: скорость/ходьба на тике
**первого выстрела** (VelIndex — центральная разность по индексу сэмплов, работает
на произвольном тике, не только в сетке кадров), flash_duration, ближний тиммейт,
живые союзы/враги. Теги: `moving_shot` (скорость >50), `isolated` (ближний тиммейт
>800 юнитов; последний выживший не помечается), `flashed` (flash >1.5 c),
`missed_first`, `overshoot`/`undershoot` (угловая динамика, единый источник с
счётчиком), `strong_duel` (выиграна HS без ошибок), `outnumbered` (фронтовый разрез).
`shift_peek` — дисциплинный признак (context.attackerWalking), ошибкой не считается.
`winProb` дуэли — кадр winprob строго до килла (килл не «подтверждает сам себя»).

## Win probability (`pipeline/winprob.py`)

Эвристика по кадрам: живые/5 + средний HP + снаряжение (вес 0.55/0.45),
нормировка [0.05, 0.95]. Пост-плант решает бомбовое время (C4 — 40 с,
дефьюз 5 с с kit / 10 с без, скорость CT 250 u/s, ETA учитывает дистанцию до
бомбы): детонация → 0.05, выполненный дефьюз → 0.95, мёртвые CT → 0.05; активный
дефьюз аннулирует fallback-фьюз (расчёт по прогрессу дефьюза против остатка таймера).
Окно после планта ограничено концом раунда (кадры ресета следующего раунда не
учитываются). Мёртвые T — CT обязаны разминировать: активный дефьюз завершится до
взрыва → 0.95, не завершится → 0.05; без активного дефьюза — успевают
(kit + путь до бомбы) → 0.95, иначе линейный спад до 0.05. Обе стороны живы:
буст ×1.5 к T; < 5 c до взрыва → 0.05 (дефьюз невозможен даже с kit, перебив T
бомбу не остановить); 5–10 c → ×1.8 если у живого CT kit, ×2.2 если нет
(расчёт на kit с трупа).

## Моменты реплея (`playeranalytics.build_moments`)

Типы: clutch (старт клатч-ситуации), multikill (≥3 килла, у первого),
openingDeath, mistake (смерть с ошибочными тегами), teamkill, swing. Свинги —
наибольшие сдвиги winprob за скользящее окно 8 с (`SWING_WINDOW_SEC`) строго
внутри раунда (кадры за `endTick` уже относятся к ресету следующего раунда),
порог 20 п.п., до 2 непересекающихся окон на раунд; «решённые» состояния
(<0.08 / >0.92) игнорируются, чтобы коллапсы на границе раунда не давали фейков
40–50 п.п.; slow-качели 95↔5 за 20–30 с детектируются окном, хотя пошаговая
дельта кадра ~1 п.п. Клику по моменту соответствует seek назад на
`max(3, min(preSec, 12))` с + автозапуск.

## Хитмапы (`pipeline/heatmaps.py`, `heatmap3d.py`) и реплей (`events.py`, `replayframes.py`)

16 слоёв точек (схемы — докстринг в `heatmaps.py`); z дописывается в конец
кортежа каждого слоя (легаси-артефакты без z читаются фронтотом с fallback на
уровень земли): kills/deaths (координаты обоих + флаги HS/penetrated/thrusmoke/
noscope), damage, shots (стрелковое), утилити-броски/ослепления (только враги),
plants/defuses, opening duels, clutches (позиция из кадров), holds (стоянки ≥5 с
вне фриза, шаг 90 юнитов, z в момент старта стоянки), positions (прореживание
~30 юнитов). Воксельная сетка для 3D (`heatmap3d.py`): живые, не в воздухе
(`is_airborne`), в раунде сэмплы позиций аккумулируются по (ix, iy, iz, игрок).

Реплей: кадры 0.125 с (payload v2: 13 полей на игрока + спарсный журнал
инвентаря `inv` с таблицей `invWeapons`), лента киллов (включая суициды/world),
трейлы гранат с разбиением по гэпу 5 с (продолжают сэмплиться после приземления —
фронт клампит дугу к окну полёта), машина состояний бомбы
(carried→dropped→planted→defused/exploded, не протекает в фриз следующего
раунда), вспышки `fl` с blind_duration (честный пирог ослепления).

## Известные упрощения

1. Победитель раунда в отсутствие `round_end` — эвристика (бомба + живые).
2. MVP раунда — max урона у победителей (нет round_mvp в FACEIT-демках).
3. «Время» — эвристически победа CT при живых обеих командах.
4. Rating/IMP/RWS — собственные приближения, не официальный HLTV.
5. counterStrafeErrors включает все движущиеся выстрелы (не только сорванные
   контрстрейфы) — интерпретировать как «дисциплину стрельбы на месте»
   (UI переименован в «Выстрелы в движении»).
6. reactionTimeMs не учитывает pre-aim дуэли против стоящих жертв.
7. Сайты A/B — эвристический маппинг id зон.
8. Разминка и события вне раундов исключены из всех метрик.
9. Бенчмарк-тиры части aim-метрик откалиброваны на старых популяциях — нужна
   рекалибровка (кластер C, отложен; см. METRICS_SPEC §11).
